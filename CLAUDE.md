## Команди

Усе запускається через `just` із каталогу `lab-N/project`. Не викликати `pip`
і не запускати `python` напряму – залежностями керує `uv`.

```
just            список рецептів
just sync       встановити залежності (uv sync)
just run        запустити лабу (uv run python src/main.py)
just lint       ruff check
just fmt        ruff format + ruff check --fix
just check      перевірка форматування + лінт, нічого не змінює
just clean      прибрати кеші (графіки не чіпає – вони трекаються)
just diagram    відрендерити блок-схему з mermaid у PNG
just reference  перегенерувати шаблон стилів ДСТУ (reference.docx)
just report     зібрати звіт у .docx
```

## Zed

Проєктні налаштування лежать у `.zed/` і комітяться:

- `settings.json` – Python на ruff + pyright, формат при збереженні, організація імпортів,
  з індексації прибрані `.venv`, `__pycache__`, `.ruff_cache`. Для підсвітки `justfile`
  треба доставити розширення Just.
- `tasks.json` – рецепти `lab: run / check / fmt / sync / clean` (`cmd-shift-p` → `task: spawn`).
  Вони запускають `just` з каталогу відкритого файлу, а `just` сам знаходить
  `lab-N/project/justfile` вище по дереву – тобто працюють у будь-якій лабі без переналаштування.

Інтерпретатор для pyright береться з `[tool.pyright]` у `lab-N/project/pyproject.toml`
(`venvPath = "."`, `venv = ".venv"`), тому кожна лаба бачить своє оточення. Там же
`extraPaths = ["src"]` – модулі в `src/` лежать пласко й імпортуються за іменем
(`import stats`), без пакета.

## Нова лабораторна

`lab-1/project` – шаблон. Для `lab-N`:

1. `cp -R lab-1/project lab-N/project` (без `.venv`, `output/`, `uv.lock` за бажанням).
2. Оновити `name` і `description` у `pyproject.toml`.
3. Розпакувати `docs/Lab_work_N/Lab_work_N.rar` у `lab-N/docs/samples/`,
   покласти `Lab_work_N.pdf` у `lab-N/docs/task/`.
4. Створити `lab-N/docs/report/report.md` за структурою з розділу V завдання.

Решта – конфіг ruff, `[tool.pyright]`, `.gitignore`, задачі Zed – уже в шаблоні
й працює для будь-якої лаби без правок.

## Вимоги до звіту

Структура (розділ V завдання ЛР): титульний аркуш → мета і завдання → результати
(синтезована математична модель, архітектурне проектування та його опис, опис структури
проєкту, результати роботи програми, програмний код) → висновки → підписи.

Оформлення взяте з курсової роботи 3 курсу (`~/Documents/kpi/3_course/2_sem/
parallel-computing-technologies/course-work/docs/report/`) – це зразок, який приймали:

- основний текст: Times New Roman 14 pt, інтервал 1.5, абзац 1.25 см, за шириною;
- таблиці: 12 pt, одинарний інтервал, суцільна сітка, шапка напівжирна по центру;
- заголовки розділів: по центру, напівжирні, великими літерами; підрозділи – зліва;
- підписи рисунків: по центру, без відступу, формат `Рисунок N – Опис` (без крапки в кінці);
- підписи таблиць: над таблицею, зліва, формат `Таблиця N – Назва`;
- лістинги коду: Courier New 10 pt, одинарний інтервал;
- поля: зверху 2, знизу 2, справа 2, зліва 2.5 см – з розділу «Технічні вимоги до звіту»
  завдання (у курсовій було 2 см з усіх боків, але тут діє вимога викладача).

Усе це – константи на початку `scripts/make_reference_docx.py` (`BODY_PT`, `TABLE_PT`,
`LINE_SPACING`, `INDENT_CM`, `MARGIN_*`).

Завдання до ЛР окремо вимагає «12 pt через 1,0 інтервал», що суперечить і ДСТУ, і зразку
курсової. Обрано варіант курсової (14 pt / 1.5) як перевірений на практиці.

Стиль тексту: лаба – не курсова, розлогих описів не треба. Структуру тримають заголовки,
жирний у тексті не використовуємо.

### Збірка .docx

Звіт пишеться в `report.md`, а `.docx` збирається з нього – вручну документ не правимо,
інакше правки загубляться при наступній збірці.

```sh
just reference                         # шаблон стилів, потрібен один раз
just diagram                           # блок-схема, після правок mermaid у звіті
just report                            # -> docs/report/report.docx
just report Прізвище_Ім'я_ІП-21_1.docx  # ім'я для здачі
```

- `scripts/make_reference_docx.py` патчить дефолтний `reference.docx` від pandoc:
  `styles.xml` (шрифт, кегль, інтервал, абзац) і `sectPr` у `document.xml` (А4, поля).
  Word для цього не потрібен. Шаблон комітиться – якщо викладач попросить іншого
  оформлення, простіше поправити скрипт, ніж документ.
- `scripts/build_report.py` готує markdown перед конвертацією: виносить титульний
  аркуш у стиль «Титульний» і додає розрив сторінки, підставляє блок-схему замість
  fence-блоку mermaid.
- Формули `$...$` pandoc перетворює на **нативні рівняння Word** (OMML), тобто їх
  можна редагувати в Word, а не вставляти картинками.
- **Титулка** відтворена з `~/Documents/kpi/3_course/2_sem/parallel-computing-technologies/
  lab2/docs/report/lab2.docx` – зразка, який приймали. Логотип КПІ витягнутий звідти ж
  (`word/media/image1.png` → `assets/00_logo.png`, 14.6 × 2.5 см). Текст по центру стилем
  «Титульний», блок «Виконав / Прийняв» – стилем «Титульний лівий» (відступ зліва 1.25 см).
  Підкреслення робиться через `[Виконав:]{.underline}`.
- Титулка розтягується на аркуш розпірками `[[space:N]]` – `build_report.py` розгортає
  їх у N порожніх абзаців. Поточне розкладання: шапка на 10 %, «Звіт» на 30 %,
  «Виконав» на 54 %, «Київ» на 94 % висоти сторінки, заповнення 96 %. Якщо текст титулки
  зміниться, підкрутити числа в `[[space:N]]`.
- У титулці підкреслення знизу пишемо екранованими: `\_\_\_`. Без екранування markdown
  з'їдає підряд ідучі `_` як розмітку курсиву.
- **Блок-схема**: pandoc не рендерить mermaid, тому `scripts/render_diagram.py`
  витягує блок mermaid із `report.md` і проганяє через `npx @mermaid-js/mermaid-cli`
  у `assets/00_blockscheme.png`. Джерело діаграми лишається у звіті – markdown
  коректно рендериться в Zed, а `.docx` отримує картинку. Правиш mermaid –
  переганяєш `just diagram`. Перший запуск тягне headless Chromium (~200 МБ),
  далі бере з кешу npx.
- У блоці mermaid важливий рядок `%%{init: ... 'wrappingWidth': 640}%%`: без нього
  mermaid переносить мітки на кількох рядках, діаграма виходить вузькою й високою
  (1:4.9) і в .docx розтягується на кілька сторінок. З ним співвідношення 1:1.6,
  тобто рівно під аркуш А4.

## Корисне

- У системі **немає poppler**, тому вбудоване читання PDF падає. Текст із завдань
  дістається так:
  ```sh
  uv run --quiet --with pypdf python -c "
  from pypdf import PdfReader
  r = PdfReader('lab-1/docs/task/lab-1.pdf')
  print('\n'.join(p.extract_text() for p in r.pages))
  "
  ```
- Реальні дані (`Oschadbank (USD).xls`, `Data_Set_*.xlsx`) читаємо просто з `docs/`
  через `src/paths.py` – не копіюємо бінарники в `project/`.
- Програма пише графіки й експорти в `lab-N/docs/report/assets/`, а не в `project/`.
  Вони комітяться, тому звіт лишається самодостатнім і картинки в ньому не б'ються
  після клону. Звіт посилається на них відносним шляхом `assets/...`.
- Приклади викладача (`lab-1/docs/samples/*.py`) написані в процедурному стилі під
  старі версії numpy/pandas. Використовуємо їх як референс алгоритмів, а не як взірець
  стилю: наш код – типізований, розбитий на модулі, без `np.random.*` глобального стану
  (беремо `np.random.default_rng(seed)`).
